접근 매트릭스

소스에서 찾은 가드를 읽어, 각 엔드포인트에 어떤 호출자가 접근할 수 있는지 마크다운 표로 보여줍니다.

-f access-matrix는 엔드포인트마다 한 행, 호출자 종류마다 한 열인 마크다운 표를 출력합니다. 각 칸은 그 호출자가 Noir가 경로에서 찾은 가드를 통과하는지 나타냅니다.

사용법

noir scan . -f access-matrix --no-log

매트릭스는 태그로 만들기 때문에, -T나 --use-taggers로 태거를 직접 고르지 않으면 이 형식은 모든 태거를 실행합니다. 로그에는 Running all taggers (implied by -f access-matrix).가 출력됩니다.

출력 예제

| Endpoint | `anonymous` | `authenticated` | `role:ADMIN` | `role:MANAGER` | `role:USER` | Requires |
| --- | --- | --- | --- | --- | --- | --- |
| `DELETE /api/admin/users/{id}` | - | - | Y | - | - | `role:ADMIN` |
| `POST /api/posts` | - | - | - | - | Y | `role:USER & authenticated` |
| `DELETE /api/posts/{id}` | - | - | Y | Y | - | `(role:ADMIN \| role:MANAGER) & authenticated` |
| `GET /posts/:id` | - | ? | ? | ? | ? | `authenticated & unresolved` |
| `GET /api/public/health` | Y | Y | Y | Y | Y | no guard found |

Y allowed, - denied, ? unknown (a guard noir could not read)

열

열 의미
anonymous 로그인하지 않은 호출자입니다.
authenticated 역할, 권한, 스코프 없이 로그인한 호출자입니다.
role:X, permission:X, scope:X 그 값 하나만 가진 로그인한 호출자입니다. 스캔에서 어떤 엔드포인트가 요구하는 값마다 열이 하나씩 생깁니다.
Requires Noir가 읽은 요구 조건입니다. 아래에서 설명합니다.

칸

표시 의미
Y 호출자가 Noir가 찾은 모든 가드를 통과합니다.
- 가드 하나 이상이 호출자를 거부합니다.
? 호출자를 거부하는 가드는 없지만 unresolved 가드가 있어 Noir가 판단할 수 없습니다.

-가 ?보다 우선합니다. 가드 하나가 호출자를 거부하면, 다른 가드를 알 수 없어도 칸은 -입니다.

Requires 열

요구 조건은 모두 만족해야 하는 조건의 목록이며 &로 이어집니다. 괄호 안의 조건은 그중 하나만 만족하면 되며 |로 이어집니다.

  • unresolved는 Noir가 찾았지만 읽지 못한 가드입니다. 빈(bean) 메서드 호출, 다른 파일의 상수, 사용자 정의 가드 클래스가 그 예입니다. JSON 출력은 각 가드의 소스 텍스트를 태그의 requires 필드에 남깁니다.
  • deny는 Spring denyAll()처럼 모든 호출자를 거부하는 가드입니다. 그 행의 모든 칸은 -입니다.
  • no guard found는 Noir가 경로에서 가드를 찾지 못했다는 뜻입니다. 경로가 공개로 선언되었다는 뜻은 아닙니다. 소스가 익명 호출자에게 열어 둔 경로(예: Noir가 anonymous 태그를 붙인 Quarkus @PermitAll 메서드)는 여기에 anonymous로 표시됩니다.

요구 조건의 출처

Noir는 엔드포인트의 태그에서 요구 조건을 읽습니다.

  • requires 필드가 있는 태그(JSON 출력 참고)는 적힌 조건을 그대로 씁니다. 이 필드를 채우는 출처는 아래 표에 있습니다.
  • requires가 없는 auth 태그는 authenticated & unresolved로 읽습니다. 태그는 가드가 있다는 것만 알려 주고, 무엇을 검사하는지는 알려 주지 않습니다.
  • requires가 없는 authz 태그는 unresolved로 읽습니다.
  • anonymous 태그는 anonymous로 읽습니다. 다른 태그의 가드를 없애지는 않습니다. 핸들러는 익명 호출자를 허용하지만 필터 체인이 로그인을 요구하는 경로는 anonymous 열에 여전히 -가 표시됩니다.
출처 요구 조건으로 읽는 것
Spring Security @PreAuthorize와 @PostAuthorize 식, @Secured, @RolesAllowed, 필터 체인 규칙
NestJS @UseGuards, 전역 가드, @Roles, @Permissions, @Scopes
ASP.NET Core, FastEndpoints [Authorize]의 역할과 정책, RequireAuthorization(라우트 빌더 확장 메서드의 호출 지점 포함), Razor Pages와 Blazor의 [Authorize] 및 페이지 규칙, 엔드포인트의 Roles, Permissions, Scopes
Django, Django REST framework login_required, permission_required, 인증 믹스인, permission_classes, LoginRequiredMiddleware
Laravel 라우트·그룹·컨트롤러 미들웨어, can:, Spatie 역할과 권한, Sanctum과 Passport 스코프, authorize()
FastAPI fastapi.security 스킴, Security(..., scopes=[...]), 의존성의 역할 검사
Quarkus, Micronaut @RolesAllowed, @Authenticated, @PermissionsAllowed, quarkus.http.auth.permission.* 정책, @Secured
Vert.x, Vaadin, Dropwizard vertx-web 인증·인가 핸들러, @RolesAllowed / @PermitAll / @AnonymousAllowed, 필수 @Auth 주체
Express, Hono Passport, express-jwt, express-oauth2-jwt-bearer, express-jwt-authz, express-basic-auth, Hono의 jwt, bearerAuth, basicAuth를 미들웨어 체인 전체에서 읽음
Ruby on Rails before_action 체인, Devise authenticate_*!와 라우트 블록, Rolify has_role?, CanCanCan authorize!
Flask Flask-Login, Flask-JWT-Extended, Flask-Security, Flask-HTTPAuth, Flask-AppBuilder 데코레이터, before_request 훅
Tornado, Sanic, Odoo, Frappe, Chalice, Home Assistant @tornado.web.authenticated, sanic-jwt @protected와 @scoped, auth=, allow_guest=, authorizer=, requires_auth
Symfony #[IsGranted], @Security, security.yaml의 access_control
Drupal, WordPress, Nextcloud, Yii, CakePHP 라우트의 _permission과 _role, permission_callback, 컨트롤러 어트리뷰트, AccessControl 규칙, Authentication 컴포넌트
Encore, Huma //encore:api와 api({ auth, expose })의 접근 수준, Operation.Security
OpenAPI 2와 3 security의 스킴과 스코프
Azure Functions, Serverless Framework 인증 수준, authorizer, private

값은 소스에 적혀 있을 때만 읽습니다. 애플리케이션 코드가 결정하는 부분은 unresolved로 남습니다. 커스텀 가드나 정책, 다른 파일의 상수, 가드를 끌 수 있는 설정, Noir가 읽지 못한 NestJS 역할 가드가 여기에 해당합니다. Go 라우터 미들웨어, Ktor, Rust 프레임워크 등 그 밖의 프레임워크 태거는 아직 요구 조건을 기록하지 않습니다.

이 포맷은 기본으로 모든 태거를 실행합니다. --use-taggers를 쓰면 지정한 목록에 프레임워크 인증 태거를 추가합니다. 가드 태그 없이 만든 표는 모든 경로를 열린 것으로 보여 주기 때문입니다.

엔드포인트의 모든 태그에서 나온 조건은 모두 만족해야 합니다. 행이 둘 이상의 프로젝트에서 오면 Project 열로 구분합니다. 외부로 나가는 클라이언트 호출(Feign, @HttpExchange 선언)은 애플리케이션이 호출할 뿐 제공하지 않으므로 표에서 제외합니다. HTTP가 아닌 경로는 포함합니다.
