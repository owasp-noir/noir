Noir는 엔드포인트마다 1-hop 핸들러 callee를 찾을 수 있는 만큼 붙여 줍니다. callee는 라우트 핸들러 본문 안에서 바로 호출되는 함수, 메서드, 프레임워크 호출입니다. AI SAST 도구와 코드 리뷰어가 다음에 볼 코드를 고를 때 도움이 됩니다.

`--include callee`로 켭니다.

```bash
noir scan . --include callee
```

이 플래그는 plain 출력뿐 아니라 모든 출력 형식에 적용됩니다. JSON, JSONL, YAML, TOML은 엔드포인트의 `callees` 필드를 채웁니다(플래그가 없으면 비어 있습니다). OpenAPI 2.0/3.0은 operation 단위 `x-noir-callees` 확장을 추가하고, SARIF는 `result.properties.noir.callees`에 담고, Postman은 item 설명에 읽기 쉬운 목록을 덧붙입니다. cURL, HTTPie, PowerShell, only-url, only-param처럼 명령이나 필터 용도의 출력은 본래 출력이 바뀌지 않도록 callee를 넣지 않습니다.

`path`와 `line`은 찾을 수 있는 만큼 찾은 위치입니다. 대부분의 분석기는 호출 위치를 기록합니다. 정의를 추적할 수 있는 분석기는 callee가 정의된 위치를 찾으면 그곳을, 못 찾으면 호출 위치를 기록합니다.

## 완성도 참고사항

- Callee는 1-hop까지만 봅니다. Noir는 호출을 따라가는 전체 call graph를 만들지 않습니다.
- 동적 디스패치, 미들웨어 체인, 데코레이터, 매크로 확장, 생성된 코드, 리플렉션 뒤에 있는 호출은 정적 추출에서 빠질 수 있습니다.
- 이름 있는 핸들러를 쓰는 프레임워크가 동적이거나 인라인 콜백이 많은 프레임워크보다 callee를 더 잘 잡습니다.
- 정의 추적은 조금씩 넓혀 가는 중이며, 지금은 분석기마다 지원 여부가 다릅니다.
- 받는 도구가 쓰기 편하도록 callee는 엔드포인트마다 중복을 없애고 개수를 제한합니다.
- renderer나 request accessor 같은 프레임워크 헬퍼는 엔드포인트가 입력과 출력을 어떻게 다루는지 보여 주므로 일부러 남겨 둡니다.
